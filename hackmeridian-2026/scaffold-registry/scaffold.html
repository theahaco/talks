02

Stellar Scaffold

From idea to working dApp, fast.

A toolkit for full-stack Stellar apps. One command gives you Rust smart contracts, a React or Svelte frontend, a local network, and typed TypeScript clients that rebuild every time your contract changes.

Same first line as the handout they're holding. One command: contracts, frontend, local network, typed clients. ~30s.

The big idea

Every save rebuilds, redeploys and regenerates your typed client. Spend the weekend on your app, not the plumbing.

One sentence to hold onto for the next seven minutes. ~10s.

The hackathon problem

  • Build Rust → Wasm
  • Deploy, copy the contract ID
  • Generate bindings, paste the ID into the frontend
  • Wire up a wallet and network config
  • …then change one function and do it all again
This plumbing eats the first day of a hackathon. Scaffold makes it one loop. ~30s.

Three things to remember

scaffold.yml = your dependencies

Your app's contract dependencies, per network: what they are and where to get them.

Secrets and machine settings go in .env.

app-lib/clients = generated

A typed client per contract, per network, regenerated on every build and gitignored. Import by name; never paste an address.

Don't edit it: wrap clients under app/.

npm run dev = the loop

Save a contract and it rebuilds, redeploys on the local network, and regenerates its client.

App runs at localhost:5173.

These are the three boxes at the top of the handout. ~45s.

1–2Set up and start a project


cargo install --locked \
  stellar-scaffold-cli stellar-registry-cli
stellar scaffold doctor   # checks your setup
stellar scaffold init my-app   # template + package manager
cd my-app && npm install && npm run dev
    

my-app/
├── contracts/     Rust → Wasm
├── app/           your frontend
├── app-lib/       wallet, network
│   └── clients/   generated
├── scaffold.yml   dependencies
└── .env           local settings

Needs Rust, Node, the Stellar CLI, and Docker. Scaffold and Registry install together as stellar plugins.

Sections 1 and 2 of the handout. Install Registry alongside Scaffold: it's how you get to testnet later. Skip prompts with --template react|svelte|none, -p <package-manager>, -y. ~40s.

Your frontend: React or Svelte

Pick one at init. Both templates ship wallet connect, network switching, and a working GuessTheNumber component, all using the same generated clients.


import { guessTheNumber } from "@stellar-scaffold/app-lib/clients"   // both
React · GuessTheNumber.tsx

const { address, signTransaction } =
  useWallet()
const tx = await guessTheNumber.guess(
  { a_number: 5n, guesser: address },
  { publicKey: address },
)
await tx.signAndSend({ signTransaction })
Svelte · GuessTheNumber.svelte

import { address, signTransaction }
  from "../stores/wallet"

const tx = await guessTheNumber.guess(
  { a_number: 5n, guesser: $address },
  { publicKey: $address },
)
await tx.signAndSend({ signTransaction })

Prefer your own UI? --template none still gives you app-lib and the clients.

Same client call, two frameworks: React uses the useWallet hook, Svelte uses a wallet store. The contract client is identical, so switching networks needs no code change. ~40s.

The loop

Save → redeploy → typed client


/// Is the answer higher or lower than your guess?
pub fn hint(env: &Env, a_number: u64) -> Symbol {
    let n = Self::number(env);
    if a_number < n {
        symbol_short!("higher")
    } else if a_number > n {
        symbol_short!("lower")
    } else { symbol_short!("yes") }
}

Save, and Scaffold rebuilds, redeploys locally and regenerates the client:


const { result } = await guessTheNumber.hint({ a_number: 5n })
Walk through it, no live coding: add hint() to contracts/guess-the-number/src/lib.rs and save. The watcher rebuilds and redeploys to the local network and regenerates the client, so guessTheNumber.hint shows up in autocomplete in the React component. ~1 min.

3Add a contract


stellar scaffold generate contract --from oz/nft-royalties   # or --from-wizard
  

contracts:
  my-nft:                   # client name; exported as myNft
    type: workspace         # built from contracts/, deployed locally
    source: nft-royalties   # crate name in its Cargo.toml
    args:                   # constructor args, by parameter name
      owner: ${account.me}
    networks:               # where your app uses this contract
      local:

generate writes the crate but does not add it to scaffold.yml; do that yourself.

Handout section 3. Start from vetted OpenZeppelin examples; --ls lists them. ~40s.

5Go to testnet and ship

Scaffold only deploys locally. Testnet contracts go through Stellar Registry; scaffold.yml just points at them.


contracts:
  my-nft:
    networks:
      local:              # built from contracts/
      testnet:
        type: contract    # already deployed: fetch it
        source: C...      # ID from registry
    

stellar scaffold build --compile-only
stellar registry publish ...  # next talk
stellar registry deploy ...
stellar scaffold build --network testnet
npm run build                 # → dist/

Set STELLAR_NETWORK=testnet in .env. Contracts can differ between networks: make sure the app still typechecks.

Handout section 5. Big change from older Scaffold: no allow-deploy, no testnet deploys from Scaffold. Build the Wasm, publish and deploy it with Registry (that's the next talk), then point scaffold.yml's testnet entry at the deployed ID. build --network testnet fetches it and regenerates the clients. ~40s.
