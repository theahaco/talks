Stellar Scaffold

From idea to working dApp, fast.

A toolkit for full-stack Stellar apps. One command gives you Rust smart contracts, a React, Svelte or no frontend, a local network, and typed TypeScript clients that rebuild every time your contract changes.

  • Scaffold is a toolkit for full-stack Stellar apps.
  • One command gives you Rust smart contracts, a frontend, a local network, and typed TypeScript clients that rebuild whenever your contract changes.

About 20s.

The big idea

Every save rebuilds, redeploys and regenerates your typed client. Spend HackMeridian on your app, not the plumbing.

  • Read the line out.
  • The point: you shouldn't spend the hackathon wiring up builds, deploys and bindings.

The hackathon problem

  • Build Rust → Wasm
  • Deploy, copy the contract ID
  • Generate bindings, paste the ID into the frontend
  • Wire up a wallet and network config
  • …then change one function and do it all again
  • Click through the list as it builds: compile Rust to Wasm, deploy and copy the contract ID, generate bindings and paste the ID into the frontend, wire up a wallet.
  • Land the last line: change one function and you do it all again.
  • This plumbing can eat your whole first day. Scaffold turns it into one loop.

About 30s.

Three things to remember

scaffold.yml = your dependencies

Your app's contract dependencies, per network: what they are and where to get them.

Secrets and machine settings go in .env.

app-lib/clients = generated

A typed client per contract, per network, regenerated on every build and gitignored. Import by name; never paste an address.

Don't edit it: wrap clients under app/.

npm run dev = the loop

Save a contract and it rebuilds, redeploys on the local network, and regenerates its client.

App runs at localhost:5173.

  • scaffold.yml: one file listing your contracts and where each one lives, per network. Secrets stay in .env.
  • app-lib/clients: a typed client per contract, regenerated on every build. Import it by name; don't edit it.
  • npm run dev: the loop. Save a contract and it rebuilds, redeploys locally and regenerates its client.
  • If they remember nothing else from Scaffold, it's these three.

About 45s.

Set up and start a project


cargo binstall stellar-scaffold-cli stellar-registry-cli
# no binstall? cargo install --locked (builds from source)
stellar scaffold doctor   # checks your setup
stellar scaffold init my-app   # react, svelte or none
cd my-app && npm install && npm run dev
    

my-app/
├── contracts/     Rust → Wasm
├── app/           your frontend
├── app-lib/       wallet, network
│   └── clients/   generated
├── scaffold.yml   dependencies
└── .env           local settings
init asks which frontend you want

$ stellar scaffold init my-app
Creating new Stellar project in ./my-app
? Pick a framework ›
❯ react
  svelte
  none (no frontend)

Needs Rust, Node, the Stellar CLI, and Docker. Scaffold and Registry install together as stellar plugins.

  • Install both CLIs. cargo binstall downloads prebuilt binaries, so it's much faster than cargo install, which compiles from source.
  • doctor checks Rust, Node, the Stellar CLI and Docker, and tells you what's missing.
  • init asks which frontend you want: react, svelte or none. Then npm install and npm run dev.
  • Point at the tree: contracts/ for Rust, app/ for your frontend, app-lib/clients is generated, scaffold.yml lists your contracts.
  • Tip for scripts: skip the prompts with --template, -p (package manager) and -y.

About 45s.

Your frontend: React, Svelte or none

Pick react, svelte or none at init. The React and Svelte templates ship wallet connect, network switching, and a working GuessTheNumber component, all using the same generated clients.


import { guessTheNumber } from "@stellar-scaffold/app-lib/clients"   // both
React · GuessTheNumber.tsx

const { address, signTransaction } =
  useWallet()
const tx = await guessTheNumber.guess(
  { a_number: 5n, guesser: address },
  { publicKey: address },
)
await tx.signAndSend({ signTransaction })
Svelte · GuessTheNumber.svelte

import { address, signTransaction }
  from "../stores/wallet"

const tx = await guessTheNumber.guess(
  { a_number: 5n, guesser: $address },
  { publicKey: $address },
)
await tx.signAndSend({ signTransaction })

Only need contracts? stellar scaffold init my-app --template none (or pick none) skips the frontend entirely: no app/, app-lib or generated clients.

  • Both templates ship wallet connect, network switching and a working guess-the-number game.
  • Same client call on both sides; only the wallet plumbing differs: a React hook versus a Svelte store.
  • Only need contracts? --template none skips the frontend entirely.

About 40s.

The loop · 1 of 3

Edit: add a method to the contract

In contracts/guess-the-number/src/lib.rs, next to guess():


/// Is the answer higher or lower than your guess?
pub fn hint(env: &Env, a_number: u64) -> Symbol {
    let n = Self::number(env);
    if a_number < n {
        symbol_short!("higher")
    } else if a_number > n {
        symbol_short!("lower")
    } else { symbol_short!("yes") }
}

hint() is our example, not part of the template. It reuses the template's own Self::number(env), the same helper guess() calls.

  • We'll walk the loop in three slides: edit, save, use.
  • Step one: add hint() to the template's guess-the-number contract. It's our example, built on the number helper the contract already has.
  • That's the whole change: no deploy script, no bindings command.

  • Step two: save the file.
  • npm run dev notices, rebuilds the Wasm, redeploys to the local network and regenerates the TypeScript client.

The loop · 3 of 3

Use it: typed, in your frontend

In GuessTheNumber.tsx, guessTheNumber. now autocompletes hint:


import { guessTheNumber } from "@stellar-scaffold/app-lib/clients"

const tx = await guessTheNumber.hint({ a_number: BigInt(guess) })
setHint(tx.result)   // "higher" | "lower" | "yes"

A read-only call: no wallet signature needed. Same import in the Svelte template.

  • Step three: the method you just wrote in Rust is a typed function in the frontend, with autocomplete and argument names.
  • It's read-only, so no wallet signature.
  • No address and no copied bindings anywhere.

About 30s.

Add a contract


stellar scaffold generate contract --ls   # list examples: stellar/…, oz/…
stellar scaffold generate contract --from oz/nft-royalties   # or --from-wizard
  

contracts:
  my-nft:                   # client name; exported as myNft
    type: workspace         # built from contracts/, deployed locally
    source: nft-royalties   # crate name in its Cargo.toml
    args:                   # constructor args, by parameter name
      uri: https://example.com/nft/
      name: My NFT
      symbol: MNFT
      admin: ${account.me}
      manager: ${account.me}
    networks:               # where your app uses this contract
      local:

stellar scaffold generate writes the crate but does not add it to scaffold.yml; do that yourself.

  • Don't start from a blank file: --ls lists ready-made examples from Stellar's soroban-examples and from OpenZeppelin.
  • --from copies one into contracts/. Then add it to scaffold.yml yourself.
  • Walk the highlights: the key becomes the client name, type workspace means built from contracts/, source is the crate name, args are constructor arguments by name, networks says where it exists.

About 45s.

Go to testnet and ship

By default Scaffold deploys only to your local network. To ship to testnet, publish and deploy with Stellar Registry, then point scaffold.yml at the deployed contract.


contracts:
  my-nft:
    networks:
      local:              # built from contracts/
      testnet:
        type: contract    # already deployed: fetch it
        source: C...      # ID from registry
    

stellar scaffold build --compile-only
stellar registry publish ...  # next talk
stellar registry deploy ...
stellar scaffold build --network testnet
npm run build                 # → dist/

Set STELLAR_NETWORK=testnet in .env. Contracts can differ between networks: make sure the app still typechecks.

  • By default Scaffold deploys only to your local network. You can opt in to more with allow-deploy, but the recommended path to testnet is Registry.
  • The flow: compile the Wasm, publish and deploy it with the registry (that's the next talk), then point scaffold.yml's testnet entry at the deployed contract.
  • build --network testnet regenerates the clients against testnet, and npm run build gives you a static site to host anywhere.
