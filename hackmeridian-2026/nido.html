Nido gives each of your users a C-address.

  • If you're new to Stellar, one thing first: Stellar has two kinds of account.
  • A G-address is an account with keys. Often that's one key, but it can have up to twenty, each with a weight, and thresholds that say how much weight an action needs. That's multisig, built into the account. If you've used Ethereum, think of an externally owned account with multisig built in.
  • What it can limit is how many signatures an action needs. It can't say "this app may spend two XLM a day." The usual wallet is an extension and a seed phrase.
  • A C-address is a contract. Its own code decides what it allows: which passkeys or G-addresses can sign, which apps can act for it, which contracts they can call, how much they can spend, and until when. On Ethereum you'd call that a smart contract wallet, except on Stellar it's built into the network.
  • Nido gives each of your users a C-address, behind one passkey.

The old way vs with Nido

Limits

The old way: no limit

The wallet signs whatever the user confirms. The only protection is reading every popup.

With Nido: a scoped key with a cap

The user approves a key for your app, and sets how much it can spend.

Spending capAn amount per day, week or month
ExpiryThe key stops working after it
Enforced byThe account, on chain

A call over the cap is refused before anything is sent.

  • And limits.
  • With a classic wallet there's no spending limit. The wallet signs whatever the user confirms, so the only protection is reading every popup.
  • With Nido, the user approves a scoped key for your app, and that key can carry a spending cap: an amount per day, week or month. It also has an expiry, after which it stops working.
  • The account itself enforces both, on chain. If your app, or anyone who got hold of its key, tries to spend past the cap, the account refuses the call before anything is sent.
  • That's the screenshot: the game at its 2 XLM a day cap. The guess stopped before the device was asked, and it cost nothing.

  • Here's what those grants look like to the user. This is Nido's approval page, opened when the SessionGate asks.
  • Each grant from the code becomes a rule. The first grant, the game's guess function, is rule one: only guess, on the game contract. The second, XLM transfer, is rule two. Nido narrows it further: it can only pay the game contract, the one guess calls.
  • The two XLM a day from the code shows up as the cap, and the user can change it before approving. Twenty-four hours becomes the expiry, shown as a ledger number.
  • And the app's key at the bottom is the session key: a key the app holds itself, which is what will sign every guess on the next slide.
  • The user confirms with their passkey, and the gate opens.

  • Diff three: calling for the user.
  • Before, you build the transaction with the user's address as the source, then sign and send it with the wallet. That's the popup.
  • After, it's one call: submitCall, with the user's address and a function that builds the same guess.
  • And here's the part I like: there's no new round-trip through Nido. The app's session key signs each call itself, and the account checks it against the grants the user approved. Nido isn't in the loop.
  • If the user connected a classic G-address wallet instead, submitCall still signs with it the old way.
  • The passkey still matters: that's the sign-in prompt, here from 1Password, for the Guess the Number app.

About 5 min, with questions.

Likely questions:

  • Mainnet? Hosted Nido is testnet-only today.
  • Who pays fees? Nido's relayer pays for account creation and grants. The app's session key pays each call's fee; on testnet Friendbot funds it, on mainnet the app would have to.
  • Where does the session key live? In the browser's localStorage for the app's origin. It never holds the user's funds; whoever reads it can spend at most the cap until the grants expire.
  • Revoking? Not in Nido yet; grants end at their expiry.
  • Why two confirmations? Nido's grant page takes one contract per request, and a guess touches two contracts.
